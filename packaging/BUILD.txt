# Windows Screenshot Monitor packaging
# Version 1.2. GitHub Actions workflow .github/workflows/build-windows.yml
# builds both installers on Windows. Run it with workflow_dispatch on mvp-v1.
# Artifacts are ScreenshotClientSetup-1.2.exe and ScreenshotServerSetup-1.2.exe.
#
# Build on Windows 64-bit from the repository root:
#   py -3 -m pip install -r requirements.txt pyinstaller
#   py -3 -m PyInstaller packaging/client.spec
#   py -3 -m PyInstaller packaging/client_config.spec
#   py -3 -m PyInstaller packaging/server.spec
#   py -3 -m PyInstaller packaging/server_config.spec
# Output:
#   dist/RuntimeHost.exe
#   dist/RuntimeHostConfig.exe
#   dist/ScreenshotServer.exe
#   dist/ScreenshotServerConfig.exe
#
# Installers:
#   packaging/client.iss
#   packaging/server.iss
# Compile with Inno Setup on Windows. Both scripts require x64-compatible mode.
# Do not run the repository-root install.bat. That file is the old TorCap installer.
#
# Installed layout (Client):
#   C:\ProgramData\Microsoft\Windows\RuntimeHost\RuntimeHost.exe
#   C:\ProgramData\Microsoft\Windows\RuntimeHost\RuntimeHostConfig.exe
#   (folder is marked hidden + system)
# Server remains:
#   C:\Program Files\Windows Screenshot Monitor\Server
# Runtime files are not stored beside the executable.
# Client config and cache use C:\ProgramData\ScreenshotClient.
# Server config, retention state, and install manifest use C:\ProgramData\ScreenshotServer.
# RuntimeHostConfig.exe is the client settings window (requires administrator).
# ScreenshotServerConfig.exe is the server settings window.
# Saving writes that side's JSON file. Restart the matching program after saving.
# Port 55550 is not a GUI setting. Windows Python includes tkinter; do not exclude it from
# packaging/server_config.spec or packaging/client_config.spec. The capture and server
# service executables still exclude tkinter.
# Logs are created on each process start under the current user's Documents folder:
#   Documents\ScreenshotClient\Logs\YYYYMMDD_HHMMSS_CC.LOG
#   Documents\ScreenshotServer\Logs\YYYYMMDD_HHMMSS_CC.LOG
# Uninstall does not delete Documents logs.
# Application data is only deleted if the uninstall prompt is accepted.
#
# Client hardening (install script):
# - Install folder and config.json are ACL-restricted (Users: read/execute or read only).
# - Scheduled task "Runtime Host" task file is restricted so standard users cannot easily modify it.
# - RuntimeHostConfig.exe is built with uac_admin=True so changing settings prompts for elevation.
